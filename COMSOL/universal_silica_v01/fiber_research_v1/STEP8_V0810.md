# STEP8 v0.8.10 — 구조·UI / 재현 가능한 결과 계약

2026-11-20. 사용자가 STEP7과 함께 STEP8 진행을 명시했으므로 STEP7의 미완료 판정과 별도로 소프트웨어 구조·UI 작업을 진행한다. **구조 변경은 V1–V9 물리 검증을 승격시키지 않는다.** 기존 flat 파일·명령·Colab·웹 경로를 유지하며 facade namespace를 추가한다.

## 파일 맵

| 요청 영역 | 안정 API 경로 | 위임하는 기존 자산 |
|---|---|---|
| geometry | `lswave/geometry/` | `geometry.py` parametric CAD |
| mesh | `lswave/mesh/` | Gmsh labeled mesh, quality, modal_study |
| materials | `lswave/materials/` | `materials.py` index/provenance |
| solver | `lswave/solver/` | original mixed vector FEM / sparse spectrum |
| postprocess | `lswave/postprocess/` | canonical scalar helpers + formula registry; existing STEP4 metrics/tracking |
| benchmarks | `lswave/benchmarks/` | STEP7 runner, actual datasets stay at `benchmarks/` |
| reports | `lswave/reports/` | canonical-input hash/version/time contract; archived reports stay at `COMSOL/validation_report/` |
| web | `lswave/web/` | JSON contract facade; live browser modules stay at `../web/` |

구조는 파일 이관 없이 추가한다. 기존 geometry.py와 같은 이름의 package를 같은 계층에 만들지 않아 Python import shadowing을 피한다. 기존 CLI는 계속 사용할 수 있다.

새 공통 진입점은 `python -m lswave.cli`다. 기존 코드 복제/재작성 대신 내부 구현으로 위임한다. Python은 계산·집계, ES modules는 JSON 검증·표시를 담당한다. 웹에서 대형 vector FEM/Bloch 고유계를 계산하지 않는다.

## 단일 공식 근거 / 값 추적

`lswave/postprocess/formulas.json`은 공식·입력 단위·결과 단위·출처·적용 범위의 중앙 registry다. `formulas.py`는 실행 가능한 문자열 eval 없이 검증된 연산을 구현한다. 공통 signed loss·gamma 및 actual Gauss Aeff는 기존 postprocess API도 이 연산에 위임하도록 연결했다. D/B/κ/overlap/ARROW/V_PCF 정의도 registry에서 검토할 수 있다. 기존 scalar JS/legacy demo를 재작성해 다른 계산법으로 바꾸지 않는다. 물리 알고리즘의 파생·미분/모드 추적 구현은 기존 검증 모듈을 사용한다.

새 모드 실행은 actual physical-domain Gauss Et²/Et⁴를 Python에서 적분하고 P, Q, 적분점 수, PML 제외 여부, Aeff 결과를 `calculation_basis`에 기록한다. 희소 field_samples를 정밀 적분하지 않는다. 큰 Gauss 배열은 기본 결과에서 제거하며 `--retain-quadrature` 선택 시 보존한다. α는 signed Im으로 계산하고 총손실과 순수 confinement loss를 구별한다. 출처 없는 n2/도핑/PM 값은 새로 가정하지 않는다.

웹 **실행·계산 근거 STEP8 → 계산 근거 보기**에서 공식·대입값·결과·단위·출처·scope를 표시한다. 실제 6성분 모드 장은 기존 STEP3 뷰어로 함께 전달한다. 물질 n(x,y) 지도는 실제 triangle centroid와 domain label에 해당하는 base material n을 표시하며, PM/bend tensor나 유효 cladding index를 의미하지 않는다. index guiding의 기존 radial n(r) 뷰는 유지한다. 손실 vs λ/분산 및 bandgap map은 같은 워크벤치의 기존 STEP4/5 탭과 연결한다.

## 입력 해시·버전·시각

새 안정 API의 모드/스윕/Bloch 결과에는 `input_sha256`, `solver_version`, `timestamp_utc`, `app_version`, `result_contract_version`, `provenance.canonical_input_json`을 기록한다. input SHA256은 **포함한 canonical UTF-8 문자열 그 자체**에 대한 값이다. 모드/스윕은 design과 n_modes·target·파장 배열 등 실행 옵션을 input_manifest로 함께 해시한다. manifest.design과 result.input도 일치해야 한다. 브라우저는 그 문자열의 SHA256을 검증하고 JSON.parse 결과와 result.input을 구조적으로 비교한다. 1.0/1, e-07/e-7, 한글 escape 방식의 재직렬화 차이를 잘못된 hash 실패로 판단하지 않는다.

입력 hash는 서명이나 물리 인증서가 아니다. 외부 PM 재료/tensor/stress 등은 해당 모듈의 별도 provenance를 같이 확인한다. 기존 CLI/이전 결과 파일은 그대로 호환하며 hash가 없으면 “이전 결과·근거 누락” 경고로 표시한다. 새 계약을 기존 모든 archive에 소급해 만들어 넣지 않는다. 새 결과의 입력/해시가 변조됐거나 버전·실행 시각이 없으면 STEP8 importer는 거절한다. 설계를 변경하면 근거 표·재료 지도·저장 가능 결과를 무효화한다.

## 로컬 / Colab 실행

`fiber_research_v1`에서 기존 requirements를 설치하고 실행한다. Colab에서도 같은 디렉터리를 작업 경로로 사용하며 결과 JSON을 다운로드해 웹으로 가져온다.

```bash
python -m pip install -r requirements.txt
python -m lswave.cli solve design.json --modes 2 --out mode_result.json
python -m lswave.cli verify mode_result.json
python -m lswave.cli sweep design.json --start 1510 --stop 1590 --points 9 --out tracked_sweep.json
python -m lswave.cli bloch bands_input.json --out bands_result.json
```

mode_result는 STEP8 또는 STEP3로, tracked_sweep은 STEP4로, bands_result는 STEP5로 가져온다. 구형 파일 포맷은 해당 기존 탭에서 계속 지원한다. 대규모 raw Gauss JSON은 브라우저 용량 한도를 넘을 수 있으므로 Python에 보관한다.

## 검증·한계

actual FEM 예시 `benchmarks/step8_v0810/example_mode_result.json`으로 2개 모드, 실제 material map, α/Aeff 근거를 검증한다. Unicode/숫자 표현·입력 변조·metadata 누락·old-result 경고·기존 formula 단위 동등성 및 실제 UI/모바일/무효화 시험을 수행한다. 소프트웨어 회귀시험 통과와 STEP7 물리 gate를 별도로 보고한다.

STEP7 재실행에서 문헌 FSM/ARF benchmark의 공기 n=1 조건을 명시적 constant 입력으로 맞춘다. 기존 air 모델 n=1.00027과 “ambient unspecified” provenance는 호환성을 위해 유지하며 출처 있는 조성/압력/온도 모델로 전용하지 않는다. 이는 근거 없는 상수 변경이나 “검증 통과” 조정이 아니다.

외부 자료가 없는 V2/V3, 수렴/모드 식별이 부족한 V6/V7는 계속 근거 필요/FAIL이다. 완전 ESM·극소 HCF loss·실제 PM 재료·정량 접속손실 인증은 하지 않는다. STEP8은 backward-compatible namespace와 결과 계약을 제공하며 기존 전체 scalar application을 새 플랫폼으로 재작성한 것이 아니다.
