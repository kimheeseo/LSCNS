# STEP8 v0.8.10 설계 / 승인 범위

사용자가 STEP7과 STEP8을 함께 명시했다. STEP7의 미완료 판정을 먼저 보고한 뒤 STEP8 소프트웨어 작업을 별도 진행한다. 물리 gate를 통과했다고 주장하지 않는다.

기존 flat modules/CLI/Colab 경로를 이동·교체하지 않고 lswave namespace에서 geometry/mesh/materials/solver/postprocess/benchmarks/reports/web로 역할을 분리한다. 원 구현은 위임하고 새 입력 계약·공식 registry·보고서와 browser 표시를 분리한다. legacy assets와 API는 유지한다.

새 result contract 1.1.0은 design+실행 옵션 manifest의 정확한 canonical UTF-8 bytes SHA256, solver_version, UTC timestamp, app_version을 포함한다. browser는 hash와 구조적 입력 일치를 검증하며 metadata가 없는 old result는 warning으로 구별한다. hash는 물리 인증이나 서명이 아니다.

새 Python 경로에서 Gauss integrals를 집계한 α/Aeff basis와 base material n map을 제공하고 희소 display sample을 정밀 적분하지 않는다. 기존 scalar n(r), STEP3 6성분 장, STEP4 손실/분산 sweep, STEP5 bandgap은 같은 UI에서 계속 연결한다. 공식은 registry/공통 evaluator를 사용하고 큰 vector 계산은 Python에 둔다.

수용 기준: Unicode/float canonical bytes, input/실행 옵션 tampering 거절, metadata 누락/legacy 경고, old loss/gamma 단위/숫자 문자열 호환, 실제 solver로 생성한 두 모드·Gauss basis·material map, actual browser/mobile/무효화/전역 ID 검사, 기존 STEP1–7 회귀. 검증 판정은 구조/UI와 물리 suite를 별도로 기록한다.
