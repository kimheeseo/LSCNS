# Capacity design v8.0.0

기존 장비별 설계에 용량 기반 빠른 견적 / 상세 설계를 추가합니다. 요구조건의 **용량** 버튼으로 진입합니다. GitHub Pages에서 브라우저 내 계산하며 서버·API 키가 필요하지 않습니다.

## 입력과 설정

- `15GW`, `GPU 10,000개`, `랙 2,000개, 랙당 10kW`, `서버 500대`, `GB200 NVL72 랙 500개` 또는 명시적 단위를 입력합니다.
- 전력은 기본 IT 부하입니다. 시설 전체 전력 기준도 선택할 수 있으며 시설 전력 = IT × PUE, IT = 시설 ÷ PUE로 변환합니다. 전력 인입 한도는 시설 전체 전력과 비교합니다.
- AI 학습 / AI 추론 / 범용 클라우드 / 코로케이션을 제공합니다. 범용 8-GPU 서버, CPU 서버, GB200 NVL72 계획 프리셋을 선택·복제할 수 있습니다.
- `capacity-design.config.json`에 단위·장비·용도·네트워크·거리·매체·BOM·가정을 보관합니다. 각 계수는 `value`, `unit`, `source`, `confidence`, `status`를 갖습니다. 공식 URL은 확인된 항목에만 붙입니다.
- 사용자 수정은 출처가 사용자 입력으로 변경되며 검증 상태를 자동 승격하지 않습니다. 가정·프리셋·입력은 브라우저에 저장하고 JSON으로 가져오기/내보내기할 수 있습니다. 저장 공간 부족 시 세션 계산은 계속되며 재접속 보존은 보장되지 않습니다.
- 전체 설정 JSON에서 매체별 속도·reach·심수·커넥터 프로파일을 수정할 수 있습니다. 위 조건은 실제 SKU의 호환 보증이 아닙니다.
- Phase는 블록 시작/끝 번호로 지정합니다. 미지정 블록은 Phase 1입니다. 범위 중복·존재하지 않는 블록은 오류로 표시하고 이전 결과를 내보내지 않습니다.

## 계산 체인

1. 단위 정규화와 전력 기준 환산.
2. IT 전력 → 랙 수. 랙 전력은 compute 외 네트워크·스토리지·여유를 포함합니다.
3. compute 배분 전력·RU로 서버/랙 한도를 구하고 서버·GPU를 환산. GPU 입력은 서버 단위 올림, NVL72는 완전한 랙 단위 올림. 전력 입력은 장비를 예산 내 내림하며 마지막 미충원 랙/블록을 보존합니다.
4. 건물 → 홀 → 네트워크 블록 분할. 스위치 포트 한도에 맞춰 실제 블록 크기를 축소할 수 있습니다.
5. 컴퓨트/스토리지/관리망의 서버 endpoint 포트를 별도 계산. 각 망의 단일/이중 패브릭을 독립 반영합니다.
6. Leaf 다운/업 포트, Spine 예약 포트, 오버서브, 블록 간 링크를 산출. 링크는 양단 포트 사용량과 검증합니다.
7. 랙 내/열 내/홀 내 거리 분포를 정수 링크에 배분. 반올림 후 링크 합계를 보존합니다. 여유장 포함 유효 길이로 DAC/AOC/MMF/SMF를 선택합니다.
8. 설치량 → 별도 예비품 → 구매량 → ±계획 수량 범위를 구합니다. 통계 신뢰구간이 아닙니다.
9. DCI는 건물 간 star/ring 계획을 별도 산출합니다. 경로 복제, SMF cable 조수, 사용/설치/예비 심선을 구분합니다. WDM은 채널과 물리 심선쌍을 구분하고 모듈/terminal/mux는 RFQ입니다.

DAC/AOC는 송수신부 일체형으로 별도 플러그형 광모듈을 더하지 않습니다. 분리형 광연결은 양단 모듈을 계상합니다. CPO 검토안은 서버 측 pluggable과 스위치 측 optical engine/ELS를 분리합니다. CPO 수량은 SKU 미선정 참고입니다.

커넥터 종단은 케이블 assembly에 포함되는 참고 수량입니다. 별도 connector 구매량으로 합산하지 않습니다. 광구간 패치리드는 따로 표시합니다. 대안 비교의 케이블 조수는 주요 assembly/트렁크만 포함하며 패치리드를 포함한 전체 BOM은 상세 표에서 확인합니다.

## 검증 결과

검증 입력은 아래 기본 가정을 사용했습니다. 공식 설치 사례의 실측 BOM 검증이 아닙니다.

- AI: 12 kW/8-GPU 서버, 8 RU, compute 설치 40 RU/랙, IT 중 compute 80%, 60 kW/랙, PUE 1.3.
- 코로케이션: 0.5 kW/CPU 서버, 2 RU, compute 80%, 10 kW/랙, PUE 1.4. 실제 테넌트 장비는 미정입니다.
- 기본 32랙/블록, 4블록/홀, 8홀/건물, 단일 패브릭. 거리·여유·규격은 설정값입니다.

| 시나리오 | IT MW | 시설 MW | 랙 | 서버 | GPU | Endpoint 포트 | 설치 링크 |
|---|---:|---:|---:|---:|---:|---:|---:|
| A: AI 학습 GPU 10,000개 | 18.78 | 24.414 | 313 | 1,250 | 10,000 | 13,750 | 27,817 |
| B: 코로케이션 2,000랙 × 10kW | 20 | 28 | 2,000 | 32,000 | 0 | 128,000 | 168,025 |
| C: AI 100MW·1개 동 | 100 | 130 | 1,667 | 6,666 | 53,328 | 73,326 | 148,320 |

### 독립 산식

A: 서버 = ceil(10,000 / 8) = 1,250. 서버/랙 = min(floor(60 × 0.8 / 12), floor(40 / 8)) = 4. 랙 = ceil(1,250 / 4) = 313. IT = 313 × 60 = 18,780 kW. Endpoint = 10,000 + 2,500 + 1,250 = 13,750. Leaf-Spine = 10,000 + 1,250 + 313 = 11,563. Core = 9 × 256 + 200 = 2,504. 총 링크 = 27,817.

B: IT = 2,000 × 10 = 20,000 kW. 시설 = 20,000 × 1.4 = 28,000 kW. 서버/랙 = min(floor(10 × 0.8 / 0.5), floor(40 / 2)) = 16. 서버 = 32,000. Endpoint = 32,000 × (2 + 1 + 1) = 128,000. Leaf-Spine = 16,000 + 16,000 + 8,000 = 40,000. 63블록을 2건물로 배분하고 2번째 건물 976랙의 DCI = ceil(976 × 10 / 400) = 25. 총 링크 = 168,025.

C: 랙 = ceil(100,000 / 60) = 1,667. 서버 = min(1,667 × 4, floor(100,000 × 0.8 / 12)) = 6,666. GPU = 53,328. Endpoint = 6,666 × (8 + 2 + 1) = 73,326. Leaf-Spine = 53,328 + 6,666 + 1,667 = 61,661. Core = 52 × 256 + 3 × 7 = 13,333. 총 링크 = 148,320. 53블록 / 4 = 14홀 필요하므로 1개 동의 기본 8홀 가정을 초과한다는 경고를 표시합니다.

15GW 입력: IT 15,000MW, 시설 19,500MW(PUE 1.3), 250,000랙, 1,000,000서버, 8,000,000GPU, 7,813블록. 개별 링크 객체를 생성하지 않고 집계합니다. 이는 기본 가정의 규모 환산이며 해당 부지·수전·네트워크 실현 가능성을 보증하지 않습니다.

```sh
node --test DCI/DataCenter/capacity-model.test.cjs
node DCI/DataCenter/capacity-browser.test.cjs
```

브라우저 테스트에는 Playwright와 Chromium이 필요합니다. `CAPACITY_CHROMIUM_BIN`으로 설치된 Chromium을 지정할 수 있습니다. 로컬 HTTP 서버를 테스트 내부에서 생성하고 종료합니다. 화면 캡처·다운로드 확인용 출력 경로는 `CAPACITY_QA_OUTPUT`입니다.

자동 검증: A/B/C 독립 산식, IT/시설 역환산과 인입 비교, 네트워크별 이중화, Phase 합계, DAC/AOC/CPO 중복 방지, 사용자 프리셋, NVL72, 비현실 입력/설정 오류, DCI/WDM, 정확한 카탈로그 규격 조건, 15GW 집계. 브라우저에서 모드·입력·가정 편집·저장/재접속·CSV/XLSX·기존 설계 전환·모바일 넘침도 확인합니다.

## 출력과 한계

- 기본 혼합안 + AOC 중심안 + SMF/트랜시버안. 선택 시 CPO 검토안 추가. 기준 수량과 ±범위를 함께 표시합니다.
- CSV/XLSX: BOM, 가정/근거, 계산 중간값, 대안, Phase, 경고와 질문. Excel에는 블록·DCI·설계 참고·제품 후보와 각 대안의 전체 BOM도 포함합니다.
- 가격 자료가 없으므로 비용·예산 충족 여부는 산정하지 않습니다.
- Tier는 요구 조건이며 인증 충족 판정이 아닙니다.
- 포트 집계는 완전 연결 또는 무손실 토폴로지 증명이 아닙니다. 큰 Super-spine 그룹의 rail·도달성 검증이 필요하며 2계층 블록 간 aggregation/gateway는 RFQ입니다. DCI의 랙당 수요는 학습 패브릭 전체 대역폭과 다릅니다.
- 스토리지 head/서버, 스위치 관리 포트, 실제 최대 소비전력, NIC cage/breakout, FEC, 광손실, 극성, 경로 분리, 국소 트레이 점유 및 패널별 용량 단편화는 별도 확인이 필요합니다.
- Phase 공용 코어/DCI 재사용 및 선행 공사 일정은 확정되지 않았습니다. 단계별 별도 설치 가정이므로 실제 재사용 계획에 따라 수량을 조정해야 합니다.
- 카탈로그 매칭은 속도·규격·패키지·커넥터·reach가 모두 확인되는 광모듈만 후보로 표시합니다. InfiniBand 장비에 Ethernet-only 카탈로그를 확정 매핑하지 않습니다. 케이블·패널의 SKU 규격 정보가 부족하면 규격만 표기하고 RFQ로 둡니다.

공식 확인에 사용한 자료: [NVIDIA GB200 NVL72](https://www.nvidia.com/en-us/data-center/gb200-nvl72/)의 GPU/랙과 액체 냉각. 랙 전력·tray·외부 포트는 별도 계획 가정입니다. 광모듈 후보는 기존 `product_catalog/YOFC/Transceiver/`의 등록 사양과 공식 URL을 사용합니다.
