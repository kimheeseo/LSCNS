## 선택 강조와 투시 재질 복원 수정

실제 Chromium에서 `문 선택 → 투시 켜기 → 선택 해제 → 투시 끄기`를 실행하면 원래 재질 대신 해제된 선택 강조 재질이 복원됐다. 선택 강조와 투시가 각각 복제한 재질을 서로 다른 순서로 해제했기 때문이다.

`scene-adapter.mjs`에서 모드 변경 전에 선택 강조를 먼저 해제하고 투시 레이어를 변경한 뒤 기존 선택과 강조 옵션을 다시 적용한다. 랙 전환 및 자원 해제에서도 같은 순서로 정리한다. 문 힌지 및 장비/연결 데이터는 변경하지 않는다.

기존 투시 브라우저 테스트에 다음 두 조합을 추가했다. 이 테스트는 수정 전 실제로 실패했고, 수정 후 통과했다.

1. 문 선택 → 투시 켜기 → 선택 해제 → 투시 끄기: 최초 material 객체로 정확히 복원.
2. 투시 켜기 → 문 선택 → 투시 끄기: 부품 선택을 유지하고, 이후 선택 해제 시 최초 material 객체로 정확히 복원.

소스/단위 39개 및 보강한 투시 브라우저 검사 1개를 다시 통과했다. 원격 통합 QA의 최종 결과는 GitHub Checks에서 확인한다.

## 구형 N-XI Preview 검사 재현

N-XI 워크플로는 `LS_Datacenter_3D_NXI_Preview.html`을 현행 진입점 파일 이름으로 복사하여 r160 기반 별도 렌더러를 검사한다. 해당 Preview 및 N-XI 코드/테스트는 main과 이 브랜치가 동일하다. 이번 r186 작업 화면과 구분한다.

동일한 정적 자산과 요청 경로를 사용하고 시스템 Chromium 실행 경로·결과 저장 위치만 바꾼 로컬 재현에서 **151개 통과, 2개 실패**를 확인했다. 반복 NPC 표본을 포함한 수치다.

- 모바일 레이아웃: iPhone 13/390px에서 viewport 376×297.8125px. 테스트는 높이 >300px을 요구하므로 실패했다. 문서 scrollWidth와 innerWidth는 모두 390px이며 가로 넘침은 없었다.
- 콘솔 404: 테스트용 정적 서버에서 발생하는 누락 요청이 콘솔 오류 검사에 포함됐다. 원격 로그인 전용 상세 로그는 읽지 못했으므로 과거 원격 실패의 모든 원인을 로컬 결과와 동일하다고 단정하지 않는다.

N-XI 검사는 생략하거나 비활성화하지 않았다. 별도 Preview의 레이아웃과 테스트 서버 문제는 현행 r186 기능과 분리해 기록했다. 병합 및 사이트 배포는 수행하지 않는다.
